# 홈 화면 "누적 거리" 목표값 자동 계산 설계

- 작성일: 2026-08-18
- 배경: 홈 화면의 "누적 거리" 진행률(`src/components/Home.jsx:90`)이 지금은 `14.2 / 25.0 km`로 하드코딩돼 있음. 목표(km)를 사용자가 따로 입력하게 하지 않고, 온보딩/프로필에서 이미 설정하는 **주간 목표 횟수**와 **목표 목적**으로부터 자동 계산하기로 함.

## 계산식

```
주간 누적거리 목표(km) = freq(주간 목표 횟수) × kmPerSession(목적)
```

목적별 1회당 적정 거리(러닝 코칭 일반 기준 — 초보~일반 러너 3~6km 범위 내에서 목적에 맞게 배분):

| 목적 | 1회당 거리(km) | 비고 |
|---|---|---|
| 체력 증진 (`FITNESS`) | 4 | 기초 체력 위주, 무난한 거리 |
| 체중 감량 (`WEIGHT_LOSS`) | 5 | 칼로리 소모를 위해 다소 길게 |
| 완주 훈련 (`RACE_TRAINING`) | 6 | 10km·하프 대비 장거리 훈련 비중 |
| 스트레스 해소 (`STRESS_RELIEF`) | 3 | 가볍게 달리는 목적이라 짧게 |

예: 목적 "체력 증진" + 주 5회 → 5 × 4 = **20.0km** 목표.

## 적용 위치

- **입력값**: `src/App.jsx`의 `goal` state (`{ type, freq }`). `type`은 지금 `src/data.js`의 `GOAL_TYPES`(한글 라벨: `체력 증진`/`체중 감량`/`완주 훈련`/`스트레스 해소`)에서 옴 — 온보딩(`Onboarding.jsx`)과 프로필(`Profile.jsx`)에서 설정.
- **출력**: `src/components/Home.jsx`의 "누적 거리" 블록(현재 하드코딩된 `14.2 / 25.0 km` 중 `25.0` 부분)을 위 계산식 결과로 교체.
- 새 유틸 함수를 `src/utils.js`에 추가하는 걸 권장: `weeklyDistanceGoalKm(goalType, freq)` — 목적별 km 테이블을 상수로 두고 `freq * table[goalType]` 반환. 순수 함수라 `node --test`로 바로 단위 테스트 가능(기존 `utils.test.mjs` 컨벤션 참고).

## 주의할 점 (구현자 확인 필요)

1. **현재 진행 거리(`14.2` 부분)는 이 설계에 포함 안 됨** — 그건 실데이터(`GET /home`의 `weeklySummary.totalDistanceKm`, `docs/API_명세서_AfterGrow_3.md` 2.1)로 채워야 하는 별도 작업(홈 화면 API 연동, 아직 미착수)이라 이 문서는 **목표값(분모)만** 다룸.
2. **`goal.type` 표기 불일치**: 프론트는 지금 한글 라벨(`체력 증진` 등)을 그대로 쓰는데, 백엔드 `PATCH /users/me/goal`(6.2)은 `GoalType` enum(`FITNESS`/`WEIGHT_LOSS`/`RACE_TRAINING`/`STRESS_RELIEF`)을 요구함. 위 표는 enum 기준으로 정리해뒀으니, 프로필/목표 API 연동 시점에 한글 라벨 ↔ enum 매핑을 어디서 할지(예: `data.js`의 `GOAL_TYPES`를 `[enum, 한글라벨, 설명]` 형태로 확장) 같이 정해야 함.
3. 목적이 아직 설정 안 된 사용자(`goal.type`이 `null`)를 위한 기본값(예: `FITNESS` 취급)도 정해두면 좋음.
