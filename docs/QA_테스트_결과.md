# AfterGrow 프론트엔드 QA 테스트 결과 (2026-08-19)

`npm run dev` + 실제 배포 백엔드(`aftergrow.duckdns.org`, vite 프록시 경유)로 회원가입부터
회원 탈퇴까지 전체 플로우를 브라우저로 직접 눌러서 테스트했다. 목업이 아닌 **실제 API 연동
기준**으로 확인한 결과다.

## 테스트 계정
- 이메일: `aftergrow.qa.test@naver.com` (테스트 종료 시 회원 탈퇴로 삭제 완료)

## 결론 요약

| 화면 | 상태 |
|---|---|
| 회원가입 (약관 동의 포함) | ✅ 정상 |
| 온보딩 (목표 선택) | ✅ 정상 |
| 홈 (UV 예보, 주간 목표) | ✅ 정상 |
| 러닝 준비 (위치·UV·스트레칭) | ✅ 정상 |
| 러닝 진행 (카카오맵, 실시간 폴링) | ✅ 정상 |
| 심박수 측정 (rPPG 카메라) | ✅ 정상 |

QA 당시 "특이사항"으로 남겨둔 두 가지는 이후 코드 리뷰로 원인을 확인했고, 그중 하나는
버그로 확인돼 같은 날 수정했다 — 아래 "특이사항 후속 처리" 참고.

---

## 1. 회원가입 → 온보딩

- 로그인/회원가입 탭 전환 UI 정상.
- 닉네임/이메일/비밀번호/비밀번호 확인 입력 + "약관 전체 동의" 체크 시 하위 3개 약관
  전부 자동 체크됨 (개별 체크도 가능).
- 가입 완료 즉시 온보딩 화면으로 전환, 서버가 발급한 닉네임("OO님 환영해요")을 바로 반영.
- 목적(체력 증진/체중 감량/완주 훈련/스트레스 해소) 단일 선택 + 주간 목표 횟수 스테퍼.
  "시작하기" 클릭 시 홈으로 이동.

## 2. 홈

- 위치 권한이 허용된 상태에서 시간대별 UV 지수 막대그래프가 실제 기상청 데이터로 렌더링됨
  (테스트 시점 "서울특별시 서초구", 현재 UV 8·매우 높음, "UV 낮은 시간대: 00~10시, 16~24시"
  추천 문구 노출).
- "이번 주 목표 N/M회" 진행률 + "러닝 시작하기" 버튼.

## 3. 러닝 준비 (Prepare)

- 진입 시 `GET /running-sessions/prepare?lat&lng` 호출, 현재 위치·UV 지수가 로딩 스피너
  ("위치 확인 중...") 이후 실제 값으로 채워짐.
- "출발 전 스트레칭"은 선택 사항 배지가 붙어 있고, 클릭하면 3단계 체크리스트 시트가 뜬다.
  각 항목은 탭하면 완료 체크(●→✓) 토글, "나중에 하고 닫기"로 건너뛰기 가능 — 실제로 스킵해도
  이후 플로우에 영향 없음.

## 4. 러닝 진행 (Tracking)

- 카카오맵이 실제로 렌더링되고 현재 위치에 마커가 찍힌다 (`VITE_KAKAO_JS_KEY` 연동 확인).
- 경과 시간이 1초 단위로 실시간 갱신.
- **`GET /running-sessions/{id}/live` 폴링에 `distanceKm`·`intensity` 쿼리 파라미터가
  실제로 실려 나가는 것을 네트워크 탭에서 확인** — API.md의 "클라이언트가 로컬 GPS 거리를
  주기적으로 같이 보내야 서버 값이 갱신된다"는 규칙이 실제 코드에 반영돼 있음.
- "러닝 종료" 클릭 시 즉시 심박수 확인 화면으로 전환.

## 5. 심박수 측정 (rPPG)

- 종료 직후 "워치 있어요 / 워치 없어요" 선택 화면. "워치 없어요"를 선택하면 rPPG 가이드 →
  카메라 측정 화면으로 이동 (CLAUDE.md에 명시된 대로 워치 경로는 이번 스프린트 목업 대상이라
  이번 테스트에서는 실사용 가능한 rPPG 경로로 진행함).
- 카메라 화면 진입 시부터 실시간 라이브 프리뷰가 바로 뜬다(2026-08-19 후속 수정, 아래
  "특이사항 후속 처리" 4번 참고) → "측정 시작" 클릭 시 12초 카운트다운, "초당 20프레임 수집" 표시.
- 12초 후 결과 화면: BPM 게이지(73 BPM), 신호 품질 "양호 · 기록에 저장됨" 노출.
  `POST rppg/start` → 12초 측정 → `POST rppg/{id}/result` 2단계 제출 흐름이 실제로 동작함.
- "재측정하기" / "솔루션 확인하기" 두 선택지 존재.

## 6. 회복 가이드

- 평균 심박·UV 노출·거리·시간 요약 카드 + "회복 가이드를 만드는 중이에요..." 로딩 후
  실제 가이드 텍스트("아주 짧은 거리에서 자외선 노출이 다소 높았어요...")와 수분 보충/세안/보습
  3단계 케어 항목이 렌더링됨.
- 쿨다운 타이머(05:00 카운트다운) UI 존재.
- "완료하고 기록 보기" 클릭 시 `recovery-guide` → `complete` 순서로 호출되고 기록 화면으로
  이동.

## 7. 기록 (History)

- 월별 달력, 상단에 이번 달 합계(러닝 횟수/거리/평균 심박) 표시.
- 기록이 있는 날짜엔 점(●) 마커 표시, 클릭 시 해당 날짜 상세 시트가 뜬다.
- 기록 없는 날짜 클릭 시 "이 날은 러닝 기록이 없어요" 빈 상태 문구 정상 노출.
- 방금 완료한 러닝이 즉시 반영됨 (1회 · 평균 심박 73).

## 8. 프로필

- 누적 러닝/거리/연속 주 통계, 목표 유형·주간 목표 표시.
- "수정" 클릭 시 인라인 편집 패널 오픈 → 목표 유형 변경 + 주간 횟수 스테퍼 조정 →
  "저장" 클릭 시 `PATCH /users/me/goal` 반영되고 프로필에 즉시 표시됨 (체력 증진/주 6회로
  변경 테스트 완료).
- 연동 상태(위치 연동/카메라 권한/위치 권한), 알림(러닝 리마인더/UV 경보) 섹션은
  현재 읽기 전용 표시로만 동작 (탭해도 토글되지 않음 — 아래 "특이사항 후속 처리" 참고,
  둘 다 의도된 설계로 확인됨).
- "로그아웃" / "회원 탈퇴" 버튼.

## 9. 회원 탈퇴

- "회원 탈퇴" 클릭 시 "정말 탈퇴하시겠어요? 되돌릴 수 없어요. 목표·알림·연동 상태와 모든
  러닝 기록이 함께 삭제돼요" 경고 + 현재 비밀번호 재확인 입력.
- 비밀번호 입력 전엔 "탈퇴하기" 버튼 비활성화(회색), 입력 후 활성화.
- 탈퇴 완료 시 즉시 로그아웃되어 로그인 화면으로 이동.
- **삭제 검증**: 탈퇴한 계정으로 재로그인 시도 → "이메일 또는 비밀번호를 확인해주세요"
  (E4011) 에러로 정상 차단됨. 계정이 실제로 서버에서 삭제됐음을 확인.

## 특이사항 후속 처리 (2026-08-19, 코드 리뷰 + 수정)

1. **[버그로 확인 · 수정 완료] 심박수 확인 화면의 "4.8km" 하드코딩.**
   `src/components/Vitals.jsx:22`에 `run.distanceKm` 대신 리터럴 문자열 "4.8km"가 박혀
   있었다. 같은 값을 쓰는 `Solution.jsx`(회복 가이드 화면)는 `{run.distanceKm.toFixed(1)}km`로
   정상 참조하고 있어서, Vitals 화면만 프로토타입 작업 중 남은 더미 문구였던 것으로 확인.
   `{run.distanceKm.toFixed(1)}km`로 교체해 실제 거리(0.0km)를 표시하도록 수정하고, 재현
   테스트로 정상 노출 확인함.
2. **[의도된 설계 · 정상] 프로필 "연동 상태"/"알림" 섹션.**
   - **연동 상태**(워치 연동/카메라 권한/위치 권한)는 조회 전용 UI로 설계된 것이 맞음 —
     `Profile.jsx`의 `PermRow`엔 애초에 `onClick` 핸들러가 없다. 값은 `navigator.permissions.query`로
     브라우저의 **실시간 실제 권한 상태**를 읽고, 브라우저가 이를 지원하지 않을 때만
     `GET /users/me/profile`이 돌려준 서버 저장값으로 폴백한다 — 서버 API 조회값을 정상적으로
     쓰고 있음을 코드로 확인, 수정 불필요.
   - **알림**(러닝 리마인더/UV 경보)은 클릭 핸들러가 없는 목업 표시가 맞음 — 의도된 설계이므로
     변경하지 않음.
3. **[코드 리뷰 중 추가로 발견 · 수정 완료] rPPG 플래시 상태 문구 오표시.**
   QA 스코프 밖이었지만 위 항목들을 검토하며 `FingerScan.jsx`를 함께 확인하다 발견. 후면 카메라
   플래시는 `MediaStreamTrack.applyConstraints({ advanced: [{ torch: true }] })`로 켜는 표준
   방식으로 구현돼 있어 안드로이드 Chrome/삼성 인터넷에서는 정상 동작할 것으로 판단되나(실기기
   미보유로 직접 트리거 확인은 못 함), 이 호출이 실패해도(iOS Safari, 플래시 없는 노트북 웹캠 등)
   화면엔 무조건 "카메라 · 플래시 켜짐"이 표시되고 있었다 — `cameraReady`만 보고 성공 여부는
   반영하지 않던 버그. `run.torchOn` 상태를 추가해 `applyConstraints` 성공 시에만 "플래시 켜짐",
   실패 시 "플래시 꺼짐 · 밝은 곳에서 측정해주세요"로 분기하도록 수정. 토치 미지원 노트북
   웹캠으로 재현 테스트해 실패 분기 문구가 정상 노출되는 것을 확인함.
4. **[기능 요청 · 반영 완료] rPPG 카메라 미리보기 실작동 + UI 정리.**
   기존엔 "측정 시작"을 누르기 전까지 카메라 화면이 회색 정적 박스였다(실제 스트림 없이
   "카메라 미리보기 · 플래시 꺼짐" 문구만 표시). 화면 진입 시 바로 `getUserMedia`로 카메라를
   켜서 실시간 라이브 프리뷰를 보여주도록 수정 — 측정 시작 시엔 이미 열려 있는 같은 스트림에
   플래시만 추가로 켜므로 재요청 지연이 없다. 손가락 위치를 알려주는 점선 가이드 링 안의
   채워진 원(빨간 점/회색 점)은 점선 테두리만 남기고 제거. 상태 문구도 정리했다 —
   - 이전엔 미리보기 단계 캡션이 라이브 영상 위에 `var(--mute)` 회색으로 겹쳐 있어 잘 안 보였다.
     측정 중 배너와 같은 스타일(하단 검은 반투명 바 + 흰 글자)로 통일해 가독성을 맞췄다.
   - 플래시는 미리보기 단계에선 애초에 항상 꺼져 있으므로, "밝은 곳에서 촬영해주세요" 안내를
     측정 시작 전(미리보기)부터 보이도록 배너 문구를 확장 — 기존엔 측정 시작 후 torch 실패 시에만
     보이던 안내였다.
   - 이 작업 중 부수적으로 발견한 버그도 같이 고쳤다: 측정 결과 화면(`done`)으로 전환될 때
     `<video>` 엘리먼트가 통째로 언마운트됐다가 "재측정하기"로 돌아오면 새로 마운트되면서
     `srcObject` 연결이 끊겨 프리뷰가 검은 화면으로 멈추는 문제 — 프리뷰 영역을 언마운트 대신
     `display:none`으로만 숨기도록 바꿔 해결.
   브라우저에서 측정 → 결과 → 재측정 사이클을 반복해 라이브 프리뷰가 끊기지 않는 것과 안내
   문구가 잘 보이는 것을 확인함.

## 확인하지 않은 것 (스코프 제외)

- 워치(애플 헬스) 경로는 CLAUDE.md 지침에 따라 이번 스프린트에서 목업 대상이라 테스트하지
  않음.
- 로그아웃 버튼 자체는 클릭하지 않음 (탈퇴 플로우로 대체 검증됨 — 탈퇴 시 로그아웃도 함께
  일어나는 것을 확인).
- PWA 설치 동작(홈 화면 추가)은 이번 테스트 범위에 포함하지 않음.
